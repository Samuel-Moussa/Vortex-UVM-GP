# Vortex UVM verification — handoff for PPT drafting + diagram generation

**Purpose of this document:** paste into a fresh Claude.ai (web) conversation to help
draft presentation slides AND generate explanatory diagrams/images for a thesis/GP
defense. This is a **headline-level summary** — it deliberately excludes coverage
percentages and bin-hit ratios (those aren't final/aren't the point of the story).
Every count below (covergroups, probes, scenarios, testing areas) is a structural
fact, verified directly from source and from real simulation runs — not an estimate.

**Project:** Vortex UVM-GP — a UVM verification environment for Vortex, an
open-source RISC-V-based GPGPU (RV32IMAF, SIMT, multi-core/multi-cluster).
**Stack:** QuestaSim 2021.2_1, Ubuntu 22.04. Primary config: 1 cluster / 1 core /
4 warps / 4 threads, AXI memory interface, scaled up to 2 clusters / 2 cores for a
multi-core config.

---

## 1. The one-sentence positioning claim

*A UVM verification environment for a RISC-V-based GPGPU, combining an independent
third-party ISA-coverage framework (Imperas' riscvISACOV) with a purpose-built
microarchitectural/SIMT coverage collector, two independently-authored golden
reference models, a bidirectional end-state scoreboard, a per-instruction lockstep
scoreboard, a register-level RAL checker, and protocol assertions.*

Do NOT claim "first published" on a slide without a literature check — say what was
built and verified, and let the gap (riscvISACOV has no SIMT concept at all) speak
for itself.

## 2. The three-layer coverage model

| Layer | Question it answers | Owner | Blind to |
|---|---|---|---|
| **L1 — ISA** | Was the *instruction space* exercised? Mnemonic, register index, operand sign, immediate | **riscvISACOV** (Imperas, third-party, independent) | Everything SIMT — it is a scalar model with no concept of a warp, a lane, or an active-thread mask |
| **L2 — microarchitecture / SIMT** | Was the *machine* exercised? Warps, divergence, masks, coalescing, hazards, caches | **Ours** (`vx_*_probe.sv` + `vortex_coverage_collector.svh`) | Operand values, per-mnemonic identity |
| **L3 — system / protocol** | Was the *interface* legal and stressed? | **Ours** (SVA assertions + collector) | — |

**Rule enforced throughout the project: L1 and L2/L3 results are never merged into
one coverage database.** They measure different axes with different denominators —
merging them would produce a number that means nothing.

## 4. The nine probes — how the coverage data actually gets extracted

All passive `bind`-based observers on the DUT (never drive it, never gate a
verdict by themselves — they feed coverage and, in two cases, a checker).

| Probe | Bound to | Role |
|---|---|---|
| `vx_sched_probe.sv` | `VX_schedule` (per core) | Warp-state coverage: active/stalled warps, SIMT split/join divergence, IPDOM stack depth, barrier, TMC/WSPAWN |
| `vx_instr_probe.sv` | `VX_dispatch` (per core) | Instruction-class coverage: ALU/branch/muldiv/VOTE-SHFL/FPU/TCU/SFU mix |
| `vx_commit_probe.sv` | `VX_commit` (per core) | Foundational retirement probe — feeds the lockstep scoreboard AND most other coverage |
| `vx_dcr_probe.sv` | `VX_dcr_data` (per core) | DCR register read-back (the bus is write-only in hardware) — feeds the RAL checker |
| `vx_lsu_probe.sv` | `VX_lsu_slice` | Recovers load **data**, not observable at the commit tap |
| `vx_cache_probe.sv` | `VX_cache_bank` (I$/D$) | Cache-event coverage: hit/miss, MSHR stall, flush |
| `vx_coalescer_probe.sv` | `VX_mem_coalescer` | Memory-coalescing coverage: fully-coalesced / partial / scattered access patterns |
| `vx_hazard_probe.sv` | `VX_scoreboard` (per issue slot) | Register-hazard coverage: RAW / WAW / both / none, per warp |
| `vx_instr_word_probe.sv` (isacov) | `VX_fetch` (per core) | Recovers the raw fetched instruction word and cross-checks it against the riscvISACOV disassembly map |
| `vortex_rvvi_shim.sv` (isacov) | `VX_commit` (per core) | Translates our retirement records into RVVI-TRACE, which drives Imperas' unmodified covergroups |

**Good diagram candidate:** a block diagram of the Vortex core pipeline (fetch →
decode → dispatch → issue/scoreboard → execute → commit) with each probe drawn as a
small tap/antenna icon at its bind point, color-coded by what it feeds (coverage
only vs. coverage + checker).

## 5. The checkers — four classes, not one, each catching something the others can't

| Checker | Compares | Catches uniquely | Blind to |
|---|---|---|---|
| **End-state scoreboard** (bidirectional) | Final DUT memory vs. SimX memory, byte-accurate | Dropped stores (reverse pass) — the DUT never wrote where SimX did | *When* something went wrong, and any value that never reached memory |
| **Lockstep scoreboard** | Every register-writeback retirement, DUT vs. SimX, per-warp program order, all lanes | A wrong intermediate value later overwritten with the right one; wrong instruction order/PC | Stores — structurally never enters this stream |
| **DCR RAL predictor** | Register write vs. a backdoor read-probe (the DCR bus is write-only) | Whether a DCR write actually landed in the RTL register | Everything except DCR config writes |
| **SVA protocol/elaboration assertions** | AXI handshake legality, config-parameter matching, DCR timing | Bus protocol violations, config mismatches, at elaboration | Functional/data correctness |

**Two golden models, two distinct roles — this is a strong, quotable point:**

- **SimX** — the full-SIMT golden reference. Every lane, every warp, every core.
  Backs the lockstep scoreboard and the end-state scoreboard.
- **Spike** (RISC-V's own reference simulator) — an **independently-authored**
  scalar cross-check, run completely offline (no DPI, no live coupling): the same
  linked ELF is fed to Spike separately, its commit log is diffed offline against a
  warp0/lane0 slice of the lockstep trace. Closes the "shared authorship" gap SimX
  alone cannot close (a misreading of the RISC-V spec shared by Vortex and SimX's
  authors would be invisible to SimX-only checking). Explicitly scoped to
  warp0/lane0/base-ISA — stops at the first Vortex-custom instruction, since Spike
  has no SIMT model at all. Proven non-vacuous by fault injection (a single
  corrupted value was caught and named exactly).

**Good diagram candidate:** a three-box flow — DUT run (produces a trace + a memory
image) → SimX run (produces the golden trace + memory) → offline comparators (the
four checkers as parallel boxes) → verdict. Then a SEPARATE small diagram just for
Spike: "same ELF" splitting into two independent processes (DUT+SimX one one side,
Spike on the other), converging into an offline 3-way diff script — emphasize NO
arrow between Spike and the simulator, to make the "no live coupling" point visually.

## 6. Verification scope — what actually gets exercised

**55 simulation scenarios** in the current suite: 33 directed kernel programs, 2
AXI-backpressure variants of existing kernels, 5 directed UVM tests, 4
regression-harness kinds, 9 riscv-dv constrained-random profiles, and 2 negative
fault-injection tests (the standing regression guard, run separately, must always
stay RED on injection).

**47 feature-level testing areas** tracked in the verification plan, spanning SIMT
control (11 areas — warp scheduling, divergence, reconvergence, barrier, TMC,
WSPAWN, predication, VOTE/SHFL, uop beats, global barrier), issue/hazards (4),
execute (10 — ALU/branch/muldiv/FPU/CSR/TCU), GPU memory (14 — coalescing, LSU,
LMEM, cache, MSHR, cross-core arbitration), bus/system (8), multi-core (3), and
termination/error-gating (2). Each area is individually tracked as closed,
partially closed, open, or deliberately waived (waived = genuinely not applicable
to this design, e.g. atomics, trap-cause classification on a machine with no trap
architecture — not skipped work).

**Recently closed, this session:**
- **Memory coalescing** (previously zero coverage on a defining GPU-memory
  behavior — new probe on `VX_mem_coalescer`, classifies fully-coalesced / partial
  / scattered access patterns)
- **Instruction-class contamination** (previously `vote.all`, `mul`, `beq` all
  silently scored as `add` — split into properly-qualified ALU/branch/muldiv/
  VOTE-SHFL coverpoints, each with a default-catch bin so nothing reads uncovered
  by omission)
- **Register hazards** (previously zero hazard coverage despite real
  hazard-detection RTL — new probe on `VX_scoreboard`, classifies RAW/WAW/both/none
  per warp from the RTL's own hazard-busy signal, no RTL modification. Also
  produced a real microarchitectural finding: WAR is *structurally impossible* on
  this design — the scoreboard only ever reserves a register on its producer's
  write, never on a read, and issue is strictly in order, so a write can never
  chase an earlier read on the same warp.)

**Remaining backlog, costed:** roughly one work-week (in the single-digit
person-days range) closes most of what's left, because the data most remaining
gaps need is already flowing through probes that are already bound — it's mostly
coverpoint-writing against existing signals, not new instrumentation. A handful of
areas (cross-core arbitration internals, cache replacement policy, the gather
unit) haven't been scoped/costed yet at all.
